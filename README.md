# GigaScribe 1.2.1 — офлайн-расшифровка аудио на GigaAM

Десктопный интерфейс с локальным движком Сбера GigaAM. Обычный пользователь Windows **не устанавливает Python, Node.js или FFmpeg и не пользуется терминалом**: после Windows-сборки он запускает `GigaScribe-Setup-Windows-x64.exe` и открывает программу через меню «Пуск».

> **Что в этом архиве:** полностью обновлённые исходники + готовый HTML/CSS/JS интерфейс + автоматическая сборка под Windows. **Готового установщика EXE внутри архива нет:** на Linux PyInstaller не создаёт Windows-бинарники. Нужен один запуск GitHub Actions на Windows или сборка на Windows-компьютере. Последний шаг сборки/запуск с настоящими весами ещё не проверены на Windows.

## Модели

| Модель | ID GigaAM | Языки |
|---|---|---|
| Русскоязычная | `v3_e2e_rnnt` | Русский, пунктуация/нормализация |
| Мультиязычная | `multilingual_ctc` | Русский, английский, казахский, кыргызский, узбекский; пунктуация не гарантируется |

**Ни одна модель не входит в установщик.** В приложении у каждой есть своя кнопка «Скачать», процент загрузки, статус и «Удалить» с подтверждением. Скачиваются `.ckpt` (и токенизатор для русской версии) с официального CDN GigaAM; контрольные суммы `.ckpt` проверяются по значениям официального загрузчика. Завершённая модель помечается отдельным маркером, недокачанная не считается установленной. Удаление одной модели не влияет на другую. При повторном запуске загрузка не повторяется. В настройках модели можно скопировать папку с файлами.

**Где хранятся модели:**
- Windows, установленная версия: `%LOCALAPPDATA%\GigaScribe\models\<имя модели>` (отдельная папка данных **GigaScribe**, не системный каталог программы `Program Files`). Так файлы не исчезают при обновлении и доступны без прав администратора.
- Windows, переносная версия: `models\<имя модели>` рядом с `GigaScribe.exe`, если там есть файл `.portable`.
- macOS (в случае будущей сборки): `~/Library/Application Support/GigaScribe/models`.
- Разработка: `./models` в корне проекта.
- Можно изменить через `GIGASCRIBE_MODELS_DIR` (для разработчиков).

Скачивание требует интернета. **После скачивания распознавание выполняется локально**, без передачи аудио в облако. Приложение поддерживает аудио до 2 ч и файлы до 200 МБ; длинные аудио разбиваются на фрагменты ~23 с. SRT содержит таймкоды фрагментов, а не точные таймкоды слов.

## Как получить Windows EXE без команд на своём компьютере

1. Загрузите **содержимое этого архива** в свой репозиторий GitHub; папка `.github/workflows/` должна сохраниться. Репозиторий может быть приватным.
2. Откройте **Actions → Build GigaScribe for Windows → Run workflow**.
3. После успешного завершения откройте этот запуск и скачайте **Artifacts → GigaScribe-Windows**.
4. Внутри будет `GigaScribe-Setup-Windows-x64.exe` (установщик) и `GigaScribe-Windows-Portable.zip` (переносная версия с `models` рядом с EXE).
5. Windows: запустите установщик, откройте GigaScribe из меню «Пуск», выберите и скачайте только нужную модель.

Для конечных пользователей команды не нужны. Для **авторов сборки** нужен GitHub; workflow использует виртуальную Windows-машину и не запускается внутри этого архива автоматически. Не подписанный цифровой подписью `exe` может вызвать предупреждение SmartScreen; публикуйте бинарник только после самостоятельной проверки его на Windows. Обычно потребуется установленный Microsoft Edge **WebView2 Runtime**; на современных Windows 10/11 он часто уже есть. Используется CPU-версия PyTorch (для совместимости); первый запуск и распознавание могут требовать много ОЗУ и места на диске. Установщик может весить сотни мегабайт или больше без весов моделей.

### Альтернативно: собрать на собственном Windows-компьютере

Для **разработчика**, не для конечного пользователя: установите Python 3.11 (доступный как `python` в PATH), Git, Inno Setup 6 и запустите `windows/build-windows.ps1` в PowerShell. Скрипт намеренно содержит только ASCII, а GitHub Actions запускает его через PowerShell 7 (`pwsh`), чтобы избежать ошибки с кодировкой Windows PowerShell 5.1. Он собирает PyInstaller `onedir`, установщик Inno Setup и переносной ZIP. На macOS или Linux этот сценарий Windows EXE не соберёт.

## Локальный запуск на Windows (без сборки EXE)

Нужны **Python 3.11** и **Git**. Откройте PowerShell в корне распакованного проекта (папка, где лежит `desktop.py`). Выполните по очереди:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt "gigaam[torch] @ git+https://github.com/salute-developers/GigaAM.git"
.\.venv\Scripts\python.exe desktop.py
```

Последняя команда открывает **самостоятельное окно GigaScribe**, без браузера; локальный сервер стартует автоматически. После первой установки можно запускать программу двойным кликом по `start-desktop.bat` или повторять последнюю команду. Node.js для этого не нужен. FFmpeg устанавливается Python-зависимостью `imageio-ffmpeg`, отдельная системная установка обычно не требуется. В режиме разработки модели хранятся в `./models` рядом с исходниками; они скачиваются только после нажатия кнопки в приложении.

Если окно не открылось, запустите именно команду `desktop.py` из PowerShell, чтобы увидеть текст ошибки. Для диагностики интерфейса без нативного окна можно запустить HTTP-сервер:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

После этого откройте `http://127.0.0.1:8000`. Он **не требуется** при запуске `desktop.py`.

### Исправление предыдущей ошибки GitHub Actions

Ошибка `Unexpected token 'Ð...'` возникала из-за кириллицы в UTF-8 без BOM, прочитанной Windows PowerShell 5.1 как ANSI. В версии 1.2.1 `windows/build-windows.ps1` ASCII-only, workflow использует `pwsh`, а проверка синтаксиса выполняется **до** установки зависимостей. Чтобы исправить существующий репозиторий, замените в нём **как минимум** два файла — `windows/build-windows.ps1` и `.github/workflows/build-windows.yml` — версиями из этого архива и сделайте commit. Затем снова запустите workflow в GitHub Actions. Для учёта новой версии установщика также обновите `windows/GigaScribe.iss`.

Если сборка после этого упадёт на **другом** шаге (установка GigaAM/PyTorch, PyInstaller или Inno Setup), это отдельная проблема: Windows-сборка и настоящий инференс с весами в этой среде пока не проверены.

## Файлы

```text
desktop.py                       Windows desktop launcher + встроенный uvicorn
backend/main.py                  API, очередь, защита запросов
backend/model_store.py           загрузка, статус, проверка, удаление моделей
backend/transcription.py         локальный GigaAM, FFmpeg, сегментация
frontend/dist/                   готовый интерфейс для десктопного приложения
frontend/src/                    альтернативный React + TypeScript UI
GigaScribe.spec                  настройки PyInstaller
windows/GigaScribe.iss           установщик Inno Setup
windows/build-windows.ps1        сборка для разработчика
start-desktop.bat                запуск окна после локальной установки зависимостей
.github/workflows/build-windows.yml автоматическая сборка в GitHub Actions
requirements-desktop.txt         UI+FFmpeg+Python зависимости
```

## Проверка

```bash
python -m pytest tests -q
```

Проверена работа API, сегментации, очереди на подменной модели, менеджера моделей без скачивания настоящих весов, статического UI, встроенного FFmpeg (если есть). Тесты **не означают**, что настоящий инференс на Windows и собранный EXE уже проверены. Сборка может потребовать правок под актуальные GigaAM/PyTorch/pywebview. Версии пакетных зависимостей upstream меняются; для воспроизводимой публикации стоит зафиксировать ревизию GigaAM и версии пакетов.
